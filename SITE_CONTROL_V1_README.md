# Site Control v1.0 — установка поверх SVGTracker V48

Это **новое приложение**, а не очередное обновление трекера. Его `main.py` не импортирует модули финансов, тренировок, заметок и расписания. Главный Telegram-бот становится служебным ботом Site Control, а главная веб-страница — административной панелью студии.

## Что входит в v1.0

- Веб-панель: список сайтов, создание проекта, редактирование текстов, контактов, услуг, шаблона, анимаций, цветов и главного изображения.
- Черновик, предпросмотр, публикация, история версий и откат публикации.
- Публичная страница каждого сайта по URL `/api/sc/public/SLUG`.
- Форма заявок, статусы заявок, уведомление владельца через клиентского Telegram-бота.
- Свой Telegram-бот на каждый проект: привязка токена из BotFather и webhook без отдельного процесса.
- Команды клиента: `/leads`, `/content`, `/items`, `/title`, `/tagline`, `/description`, `/phone`, `/address`, `/hours`, `/additem`, `/price`, `/removeitem`, `/done`, `/myid`.
- Вход в веб-панель по подтверждению в управляющем Telegram-боте. Поддержка списка администраторов из V48.
- Постоянная база `/var/lib/sitecontrol/sitecontrol.db`; токены клиентских ботов в `/var/lib/sitecontrol/tokens/` с правами `0600`; резервные копии `/var/backups/sitecontrol/`.
- Совместимый с V48 механизм ZIP-деплоя, автоматического проверки `/api/test`, GitHub-публикации и отката кода.

## ВАЖНО: что установка ZIP делает и не делает

**Делает:** заменяет основной процесс на Site Control (на прежнем `svgtracker.service`), меняет главную страницу и ассеты. Встроенный веб-сервер продолжает слушать `127.0.0.1:8000`; проверка готовности — `GET /api/test`.

**Не делает:** не удаляет автоматически старую базу `svgtracker.db`, `config.py`, токен главного бота, исторические резервные копии и старые неиспользуемые файлы (их защищает прежний ZIP-deployer). Данные V48 остаются для восстановления и не используются новым приложением. Не меняет конфигурацию Nginx, имя systemd-службы, домен, GitHub-репозиторий и username главного Telegram-бота в BotFather.

**Пока не реализовано:** собственные домены клиентов с автоматической настройкой DNS/Nginx/HTTPS; редактор произвольных HTML/CSS/JS-архивов; многопользовательские роли внутри одного клиента; полноценный каталог с корзиной и онлайн-оплатой; юридические документы/согласия для реальных заявок; продакшен-нагрузочные тесты на конкретном VPS. Это MVP, а не завершённая платформа для массового хостинга.

## Перед установкой: обязательно

1. Проверьте, что V48 сейчас исправно работает, а бот умеет делать ZIP-deploy и связан с GitHub (иначе прежний механизм установки может отклонить архив ещё до замены).
2. Создайте `/backup` в **существующем** боте SVGTracker и сохраните резервную копию **вне VPS** (вручную или через свой привычный способ). Особенно важно сохранить исходный `svgtracker.db` и папку вложений: ZIP-деплой не делает удалённый backup за пользователя.
3. Убедитесь, что ваш Nginx проксирует `/api/` на `127.0.0.1:8000` и отдаёт `/`, `index.html`, `script.js`, `product.js`, `style.css`, `product.css` из рабочего каталога. V48 уже использует этот формат.
4. Проверьте HTTPS. Авторизация сайта использует cookie `Secure`, клиентские боты — HTTPS-webhook.

## Установка с телефона

1. Откройте **текущего** Telegram-бота администратора SVGTracker.
2. Выполните `/backup`.
3. Отправьте `Site_Control_V1_From_SVGTracker_V48.zip` как **файл/документ**.
4. Нажмите **Проверить и обновить**. Старый установщик делает резервную копию, перезапускает службу, проверяет `/api/test`, синхронизирует GitHub и откатывается при ошибке.
5. После сообщения об успешном деплое откройте **старый домен трекера** в браузере: должен появиться Site Control.
6. Нажмите «Войти через Telegram», откройте главного бота и подтвердите вход ссылкой или командой `/login КОД`.
7. Создайте сайт, измените текст, сохраните, откройте предпросмотр, опубликуйте. Ссылка на публичную страницу: `https://ВАШ_ДОМЕН/api/sc/public/SLUG`.
8. Создайте клиентского бота через @BotFather, попросите владельца бота отправить `/myid`, укажите его Telegram ID в редакторе. В разделе «Telegram» вставьте токен и нажмите «Подключить».
9. Владелец должен сам начать диалог со своим ботом. Проверьте его `/content`, затем отправьте тестовую заявку с публичной страницы и убедитесь, что бот сообщает о ней и `/leads` показывает запись.

## Проверки после установки

- `https://ВАШ_ДОМЕН/api/test` возвращает JSON: `{"status":"ok","service":"Site Control","version":"1.0.0"}`.
- Админ-бот отвечает на `/admin`, `/deploy_check`, `/server_status`, `/backup`, `/rollback`.
- Неавторизованный `GET /api/sc/sites` возвращает HTTP 401.
- При публикации одного сайта в другом сайте ничего не меняется.
- `/api/sc/public/SLUG` доступен после публикации, до публикации — 404.
- Токен клиентского бота не выводится обратно в веб-панель или диагностические сообщения.
- Проверьте `/api/sc/hooks/...` — без секретного заголовка Telegram возвращает 403 (правильный URL в настройке webhook; сам путь нельзя публиковать).

## Важные настройки VPS

Параметры, которые можно задать через systemd `Environment` или файл переменных, **не включённый в ZIP**:

- `SITE_CONTROL_PUBLIC_URL=https://ВАШ_ДОМЕН` — обязательная база для Telegram webhook; если не указана, используется `SVGTRACKER_PUBLIC_URL`, затем `https://starslix.ru` (старый домен V48). Если действующий домен отличается, настройте явно перед подключением клиентских ботов.
- `SITE_CONTROL_DATA_DIR=/var/lib/sitecontrol` — база, медиа и токены (права только у процесса).
- `SITE_CONTROL_BACKUP_DIR=/var/backups/sitecontrol` — архивы данных Site Control.
- `SVGTRACKER_ADMIN_ID` — первоначальный Telegram ID владельца, сохранившийся от V48.
- `SVGTRACKER_BIND_HOST=127.0.0.1` — интерфейс внутреннего API.

Не используйте токен главного бота как клиентский: это конфликтует с его polling. Веб-интерфейс отклоняет такую попытку.

## Данные, резервные копии и откат

Новая база никак не связана с `svgtracker.db`: трекер перестаёт пользоваться старой БД, но та остаётся нетронутой. Старые резервные копии кода помогают вернуться к SVGTracker, однако **не заменяют** backups новой базы Site Control.

Команда `/backup` после перехода создаёт два архива: резервную копию Site Control (база, файлы и токены) и копию прежнего контура развёртывания. Скачивайте копии с VPS дополнительно: они расположены на том же физическом сервере.

Команда `/rollback` в новом управляющем боте подтверждает восстановление старого кода через прежний deploy-helper. При необходимости администратор VPS может выполнить откат через `deploy/admin_deploy.py rollback /var/backups/svgtracker/ИМЯ_АРХИВА.tar.gz` отдельной системной задачей; не запускайте такую команду внутри основного сервиса.

## Архитектура и требования к безопасности

Статические файлы панели обслуживает Nginx; API — FastAPI, admin polling — Aiogram; клиентские боты работают через единый webhook-маршрутизатор, поэтому новые клиенты не требуют отдельных процессов. Для MVP применяется SQLite WAL, отдельная таблица клиентов, сайтов, заявок, релизов и логов. Для следующей стадии с высокой записывающей нагрузкой рекомендована миграция на PostgreSQL и фоновая очередь.

Защита MVP: Telegram-авторизация администрации, серверные cookies HttpOnly/Secure, разделение tenant_id, права владельца клиентского бота, проверка секретов webhook, дедупликация Telegram update, ограничения размера файлов и заявок, проверка формата изображений, безопасный HTML-рендеринг, ограничение частоты заявок и входа.

Ограничения: хранение токенов в файлах с правами `0600`, а не аппаратном хранилище или KMS; общее VPS — единая точка отказа. До продажи сайтов реальным клиентам необходимо подготовить политику обработки персональных данных и согласия для формы заявок, проверить безопасность и сделать внешние резервные копии. Нагрузочное тестирование на реальном VPS не выполнялось.
