SITE CONTROL v1.5 — ИНСТРУКЦИЯ

УСТАНОВКА
1. В текущем Telegram-боте Site Control выполните /status и сохраните вне VPS резервную копию существующих данных с помощью /backup (если работает).
2. Убедитесь, что известен доступ к VPS по SSH для аварийного восстановления. Не удаляйте текущую базу и /var/lib/svgtracker-admin/admins.json.
3. Отправьте Site_Control_V15_Project_Files_Console_Backups.zip главному боту документом, подтвердите «Установить ZIP».
4. Проверьте /start, Mini App, веб-панель, список администраторов, журналы и работу существующих проектов.
5. Если Telegram сообщает «systemd-run failed», значит старый установщик не запустился и новая версия НЕ установлена. Используйте файл ВОССТАНОВЛЕНИЕ_ДЕПЛОЯ.txt внутри архива; потребуется первоначальное исправление прав на VPS.

АДМИНИСТРАТОРЫ
- ID основного администратора: 382257126.
- Дополнительные администраторы уже хранятся на сервере в /var/lib/svgtracker-admin/admins.json; архив не содержит и не перезаписывает этот файл.
- В обычном браузере для входа требуется подтверждение через Telegram.
- Mini App открывается без отдельного входа только администратору, подпись Telegram проверяется сервером. Посторонним доступ закрыт.

НОВЫЙ ПРОЕКТ
1. «Проекты» → «Новый проект» → название и короткий уникальный slug.
2. «Серверы и SSH» → добавьте IP, пользователя, порт, название службы, проект и абсолютную папку с файлами продукта (например /srv/cafe).
3. На клиентском сервере создайте отдельного SSH-пользователя с доступом на запись в папку сайта. Он НЕ должен быть root. Сгенерируйте публичный ключ кнопкой панели, добавьте его в authorized_keys, сравните отпечаток ED25519 с результатом на самом VPS, подтвердите в Site Control.
4. Вернитесь в проект → «Файлы». Загрузите index.html, отдельные файлы или ZIP с относительными путями. Можно выбрать несколько файлов: они сохранятся как последовательные подготовленные версии.
5. Выберите нужный VPS и нажмите «Опубликовать». Система создаст файловый бэкап ДО обновления. Загрузка без публикации не меняет сайт.
6. Нужное имя файла и его путь должны соответствовать файловой структуре на сервере. В ZIP допускаются только безопасные относительные пути из латинских букв, цифр, дефиса, подчёркивания и точек. Системные, скрытые, ключевые, DB и .env файлы через этот механизм не обновляются.
7. Если изменились Python-файлы, перезапустите службу через вкладку «Консоль». Существующие Nginx и маршрутизация доменов не изменяются автоматически.

КОНСОЛЬ
- В проекте выберите «Консоль» → VPS → готовую команду либо введите свою.
- На каждую команду требуется подтверждение. Для ручной команды и перезапуска — слово EXECUTE.
- Вывод команды отображается в окне. Непривилегированный SSH-пользователь ограничен разрешениями серверной ОС. Действия с sudo потребуют заранее настроенного минимального набора разрешённых команд на целевом VPS.
- Для своего VPS зарегистрируйте отдельное SSH-подключение с проектом «Наша платформа / без клиента» и затем используйте его на вкладке «Наша платформа → Консоль».

БЭКАПЫ
- «Бэкапы» → выберите VPS → «Создать копию». Перед публикацией копия создаётся автоматически.
- «Скачать» сохранит ZIP; храните как минимум одну копию вне VPS.
- Для загрузки уже имеющегося ZIP-бэкапа выберите сервер, файл через поле «Импорт ZIP-бэкапа» и нажмите «Импортировать»; импорт сам по себе ничего не перезаписывает.
- «Восстановить» запишет файлы из выбранной копии. Перед этим система создаст ещё одну страховочную копию.
- «Удалить» удалит только выбранную сохранённую копию, а не рабочий проект.
- Копии не включают внешние БД, секреты, системные каталоги и приватную административную базу. Восстановление не удаляет отсутствующие в архиве файлы.
- Для БД дополнительно настройте отдельный pg_dump/SQLite-backup и проверяйте восстановление.

ПЛАТФОРМА И ПРАВА
- «Наша платформа» — собственный Site Control, а не клиентский продукт.
- Файловые обновления собственного проекта применяются к /var/www/SVG (или SITE_CONTROL_PROJECT_ROOT), если сервису разрешена запись.
- Прямое обновление main.py не может гарантировать перезапуск службы: при необходимости перезапустите systemd через проверенный SSH-доступ.
- Рабочая база /var/lib/sitecontrol/sitecontrol.db, токены и администраторы расположены вне корня файлов для обновлений. Их ZIP не заменяет.

ЛОГИ
- «Логи и файлы» либо вкладка «Логи» в проекте: скачивание журналов Telegram, сайта/API и деплоя.
- Для журналов клиентского сервера выберите SSH-подключение на вкладке «Консоль», затем скачайте через «Логи».
- Команда /status отправляет краткое состояние текстом и прикрепляет только актуальную ИНСТРУКЦИЯ.txt; команда /logs открывает выбор журнала.

ОГРАНИЧЕНИЯ / ПОСЛЕДУЮЩИЙ ЭТАП
- Установщик V48 может сохранять старое служебное имя svgtracker.service. Резкая смена имени без SSH-миграции сломает обновление.
- Автоматическая настройка Nginx, брандмауэра, DNS, SSL, распределение трафика, запуск новых Python-служб и миграция БД не входят в MVP.
- Обновление нескольких файлов не атомарно на уровне всего релиза; при отказе возможен частичный результат. Перед запуском обязательно сохраняется бэкап, а административные действия аудируются.
