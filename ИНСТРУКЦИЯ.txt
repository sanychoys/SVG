SITE CONTROL v1.11 — УСТАНОВКА И ПРОВЕРКА С ТЕЛЕФОНА

ПЕРЕД УСТАНОВКОЙ
1. Сделайте резервную копию работающего Site Control и сохраните её вне VPS.
2. Если имеется возможность, сохраните отдельную резервную копию базы и
   реестра администраторов. Этот ZIP не содержит и не удаляет их.
3. Установите ZIP прежним установщиком Telegram либо через раздел
   «Наша платформа → Файлы → Проверить архив → Установить».
4. Если установщик выдаст systemd-run failed, установка ещё не состоялась.
   Исправление консоли внутри ZIP не может исправить права старого
   установщика до применения обновления. Нужна разовая проверка systemd по SSH.

ПОСЛЕ УСТАНОВКИ
1. Закройте Mini App и откройте заново через /start.
2. Откройте «Наша платформа → Консоль».
3. Нажмите «Нагрузка»: появится время работы VPS.
4. Нажмите «Диск»: появится занятое и свободное место раздела Site Control.
5. Нажмите «RAM»: появится память из /proc/meminfo.
6. Нажмите «Сервис»: появится состояние ТЕКУЩЕГО процесса API и его PID.
   Это не полная проверка всех отдельных systemd-служб.
7. Нажмите «Логи»: увидите последние события приложения (не весь journalctl).
8. Во вкладке «Логи» откройте «Сервер проекта» — журнал должен открыться
   без прежнего падения. Остальные журналы доступны по-прежнему.
9. Проверьте список администраторов: второй администратор должен остаться.

РУЧНЫЕ КОМАНДЫ НА НАШЕМ VPS
- Если веб-служба запущена от непривилегированного пользователя, ручные
  команды выполняются с правами этого пользователя, без повышения прав.
- Если веб-служба запущена от root, произвольный shell заблокирован.
  Разрешены точные диагностические команды: uptime, df -h, free -m,
  free -h, site-control status, site-control logs.
  Применяйте кнопки диагностики — они предпочтительнее.
- Для установки пакетов, изменения системных конфигов, перезапуска сервисов
  и произвольных команд нужен отдельно настроенный исполнитель с минимальными
  правами. НЕЛЬЗЯ давать веб-процессу unrestricted root shell.

ПРОВЕРКА СЕРВИСА ЧЕРЕЗ SSH (если ограничения остаются)
С телефона через SSH выполните и посмотрите результат:
  systemctl show svgtracker.service -p User -p Group -p NoNewPrivileges -p CapabilityBoundingSet -p SystemCallFilter
  systemctl cat svgtracker.service
  journalctl -u svgtracker.service -n 30 --no-pager

Эти команды ничего не меняют. Не отключайте NoNewPrivileges и остальные
ограничения наугад. Пришлите вывод для точной безопасной настройки.

ВАЖНО
Для обычной диагностики настройки systemd после v1.11 не требуются.
Для полноценной ручной консоли нужны отдельные права исполнения.
База проектов, файл дополнительных администраторов и секреты не
включены в ZIP.
