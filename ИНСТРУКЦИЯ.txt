SITE CONTROL V1.3 — АКТУАЛЬНАЯ ИНСТРУКЦИЯ

A. УСТАНОВКА ZIP С ТЕЛЕФОНА
1. Сначала выполните /backup; отдельно скопируйте сохранённую резервную копию
   ВНЕ VPS. Внутрисерверная резервная копия не защитит от потери VPS.
2. Отправьте Site_Control_V13_MVP_Remote_Servers.zip в главный Telegram-бот
   документом, подтвердите «Установить ZIP».
3. После успешного сообщения отправьте /start, откройте Mini App.
4. В обычном браузере откройте свой адрес Site Control и выполните вход кодом
   через главный Telegram-бот. Telegram Mini App войдёт автоматически, если
   ваш Telegram ID присутствует в списке администраторов.
5. /status — краткое состояние ТЕКСТОМ, а файлом эта актуальная инструкция.
6. /logs — выбрать журнал главного Telegram-бота или сайта/API.
7. При ошибке установки получайте трассировку из сообщения об ошибке и /logs.

Б. УПРАВЛЕНИЕ САЙТАМИ
САЙТ И MINI APP — одинаковые возможности:
1. Вкладка «Проекты» → «Новый сайт» → название компании, латинский slug.
2. Откройте проект → «Контент»/«Дизайн» → «Сохранить».
3. «Предпросмотр» → «Опубликовать». Публичный адрес сейчас вида
   https://АДРЕС-КОНТРОЛА/api/sc/public/slug.
4. Вкладка «Заявки» — обращения посетителей; «Версии» — откат публикации.
5. Вкладка «Telegram» — ID владельца, подключение его бота через BotFather.

ГЛАВНЫЙ TELEGRAM-БОТ:
/sites — список и выбор проектов.
/newsite Название компании | latin-slug — создать черновик.
/edit ID title Новый заголовок — сохранить изменение черновика.
Допустимые поля /edit: title, tagline, description, phone, address, hours, button.
/publish ID — опубликовать сохранённый черновик.
/start — кнопка Mini App, сайты, серверы, состояние, логи, ZIP, backup.
/status — краткий текст + этот TXT-файл.
/logs — логи бота или сайта.
/backup — резервная копия.

В. ДРУГОЙ VPS (ПЕРВОЕ ПОДКЛЮЧЕНИЕ)
1. На ОС центрального Site Control должен быть установлен пакет openssh-client,
   который содержит ssh, ssh-keygen и ssh-keyscan. При отсутствии на Ubuntu:
     sudo apt update && sudo apt install -y openssh-client
   Это разовая операция. Обычный ZIP не устанавливает системные пакеты.
2. В Site Control откройте «Серверы». Заполните имя, адрес/IP, порт,
   SSH-пользователя (например scdeploy), имя ключа (например client1),
   службу systemd (например nginx) и связанный проект.
3. Нажмите «Создать / показать публичный ключ», скопируйте полученный текст.
   ПРИВАТНЫЙ ключ НЕ переносите. Он остаётся на центральном VPS.
4. НА КЛИЕНТСКОМ VPS один раз настройте SSH-пользователя и установите его
   authorized_keys. Пример для Ubuntu (создайте пользователя при необходимости):
     sudo adduser --disabled-password --gecos "" scdeploy
     sudo install -d -m 700 -o scdeploy -g scdeploy /home/scdeploy/.ssh
     echo 'ВАШ_ПУБЛИЧНЫЙ_SSH_КЛЮЧ' | sudo tee -a /home/scdeploy/.ssh/authorized_keys >/dev/null
     sudo chown scdeploy:scdeploy /home/scdeploy/.ssh/authorized_keys
     sudo chmod 600 /home/scdeploy/.ssh/authorized_keys
   Не вставляйте кавычки внутри публичного ключа. Эта первичная настройка
   требует уже действующего root/sudo-доступа к клиентскому VPS.
5. Сверьте отпечаток сервера НЕЗАВИСИМО по SSH-консоли клиентского VPS:
     ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
6. В Site Control нажмите «Получить отпечаток VPS». Сверьте SHA256 с шагом 5.
   Введите вручную отпечаток из шага 5 и нажмите «Подтвердить отпечаток VPS».
7. Нажмите «Добавить сервер» и попробуйте кнопку «Нагрузка».
8. SSH-пользователь должен иметь только необходимые права. Для разрешения
   перезапуска конкретной службы, и только её, настройте sudoers вручную.
   Пример для sudoers (ИЗМЕНИТЕ nginx на свою службу, если нужно):
     scdeploy ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
   Не выдавайте scdeploy универсальные права sudo без пароля.

ГЛАВНЫЙ БОТ ДЛЯ VPS:
/servers — список подключений и выбор шаблонных действий.
/server ID uptime — время работы.
/server ID disk — диски.
/server ID memory — память.
/server ID site_status — состояние связанной службы.
/server ID site_logs — журнал systemd.
/server ID site_restart — перезапустить службу после подтверждения.
/exec ID команда — вручную исполнить однострочную команду после подтверждения.

Шаблоны SSH не означают доступ root. Команда с неподходящими правами
корректно вернёт ошибку; лишние права выдавать не рекомендуется.

Г. ОЧИСТКА СТАРОГО ТРЕКЕРА
1. Проверьте, что новая версия работает, и сохраните копию старой базы ВНЕ VPS.
2. В главном боте выполните /cleanup_legacy и подтвердите действие.
3. Очистка создаёт архив старых файлов и старой SQLite, проверяет его,
   синхронизирует удаление с Git, только затем удаляет старую рабочую БД.
4. Не удаляйте /var/lib/sitecontrol и config.py! Они нужны новой системе.
5. Старые резервные копии и имя системной службы svgtracker.service
   сохраняются для безопасной совместимости со старым установщиком.
   Их переименование/удаление требует отдельной миграции systemd и Nginx;
   данный ZIP этого НЕ делает.

Д. ОГРАНИЧЕНИЯ MVP
- Удалённый VPS можно привязать к сайту, проверять и администрировать по SSH.
- Публикация страниц Site Control пока работает на центральном сервере.
- Автовыгрузка сайта на чужой VPS, конфиг Nginx, DNS и SSL ещё не автоматизированы.
- База Site Control — SQLite (sitecontrol.db), она НЕ относится к старому трекеру.
- Поддержка нескольких VPS предполагает ограниченные права SSH-пользователей.
- Тесты проведены локально. Живая работа Telegram/webhook/SSH, Nginx и GitHub
  требует проверки именно на вашем реальном сервере.
