SITE CONTROL V1.2 — УСТАНОВКА И НОВЫЕ ФУНКЦИИ

УСТАНОВКА С ТЕЛЕФОНА
1. В главном Telegram-боте используйте /backup и убедитесь, что имеется
   резервная копия вне VPS (локальная копия важна до любой очистки).
2. Отправьте ZIP-архив как документ в чат с главным ботом Site Control.
3. Подтвердите «Установить ZIP». Установщик проверит GitHub, файлы, API;
   при неуспехе выполняется автоматический откат к предыдущему коду.
4. Отправьте /start, проверьте кнопку «Открыть Mini App».
5. Отправьте /status — бот приложит «Site_Control_Состояние.txt».
6. Отправьте /logs и выберите «Telegram-бот» либо «Сайт / API»;
   придёт TXT с последними записями. Крупные ошибки могут занимать несколько строк.

MINI APP
- /start -> «Открыть Mini App»: открывается наша веб-панель внутри Telegram.
- Авторизация выполняется по подписанным initData Telegram только для администраторов.
- В обычном браузере по-прежнему используйте кнопку «Войти через Telegram».
- Требуется рабочий публичный HTTPS-домен. Адрес определяется параметром
  SITE_CONTROL_PUBLIC_URL, либо прежним SVGTRACKER_PUBLIC_URL.
- Если кнопка ведёт не туда: исправьте адрес в конфигурации службы и перезапустите
  приложение; сам ZIP не меняет Nginx и DNS.

КОМАНДЫ БОТА (ПОКАЗАНЫ В МЕНЮ)
/start    Открыть панель и основные кнопки
/status   Получить TXT-файл с состоянием, временем и действиями при ошибке
/logs     Выбрать и получить журнал Telegram-бота или сайта/API
/backup   Создать резервную копию, которая хранится на VPS

СКРЫТЫЕ СЛУЖЕБНЫЕ ОПЕРАЦИИ
/login КОД          Резервный вход с браузера
/admin_add ID       Добавление администратора с подтверждением
/admin_remove ID    Удаление администратора с подтверждением
/rollback           Откат к резервной копии кода с подтверждением
/cleanup_legacy     Удаление остатков прежнего приложения с подтверждением

ОЧИСТКА СТАРЫХ ДАННЫХ (ТОЛЬКО ПОСЛЕ ПРОВЕРКИ V1.2)
1. Сохраните резервную копию старой БД и файлов за пределами сервера.
2. Проверьте действующие сайты, заявки, Telegram-ботов и Mini App.
3. Отправьте /cleanup_legacy и нажмите «Подтверждаю очистку».
4. Система сохранит проверенный архив в каталоге резервных копий VPS,
   удалит известные старые файлы и БД прежнего трекера и синхронизирует GitHub.
5. Данные Site Control (/var/lib/sitecontrol), токены и конфигурация не трогаются.
6. Старые бэкапы сервера, системные службы и нестандартные файлы не удаляются.
   Для их удаления понадобится отдельная проверка сервера.

ВАЖНО
- Нельзя удалять /var/lib/sitecontrol и config.py: они нужны текущему приложению.
- В старом механизме ZIP-deploy осталось историческое имя svgtracker.service —
  это только имя сервиса, а не запущенный функционал трекера.
- Текущие серверные пути и GitHub проверяются установщиком; при несинхронном Git
  ZIP может быть отклонён. Полные ошибки доступны в журнале и статусе деплоя.
- Файлы журналов хранятся в /var/lib/sitecontrol/logs с ротацией (2 МБ × 4
  файла на каждый из двух журналов). Операции и исключения не теряют traceback
  в пределах сохранённых журнальных файлов.
- При сбое Mini App нужно проверить HTTPS, SITE_CONTROL_PUBLIC_URL и /logs.
