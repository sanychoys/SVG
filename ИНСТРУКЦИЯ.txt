SITE CONTROL v1.18 — ИНСТРУКЦИЯ

УСТАНОВКА
1. Сохраните внешнюю резервную копию Site Control и реестра администраторов.
2. Убедитесь, что установщик Site Control активирован на VPS. Если обновление на сайте не применяется из-за systemd-run, откройте «Наша платформа → Консоль», включите ROOT и выполните от root:
   cd /var/www/SVG && python3 deploy/configure_update_service.py
   После этого: systemctl is-active sitecontrol-updater.path
   Ожидаемое состояние: active. Если оно не active, откройте журналы службы и устраните системное ограничение прежде, чем повторять установку.
3. Загрузите архив v1.18 в «Наша платформа → Файлы», нажмите «Проверить файл» и затем «Установить обновление».
4. Перезапустите Mini App и убедитесь, что открываются «Наша платформа», «Инфраструктура» и «Администраторы».
5. Проверка: «Наша платформа → Консоль», переключатель ROOT, команда id. У владельца команда выполняется без повторного диалога. Если служба root отключена, система сообщит об этом.

ПОДТВЕРЖДЕНИЯ ROOT ДЛЯ КОМАНДЫ
1. Откройте «Администраторы» → выберите администратора → «Настроить права».
2. Выдайте ему «Полный доступ» либо только соответствующие права platform.root/servers.root и необходимые доступы к проектам.
3. Переключатель «Подтверждать root-команды»: включён — перед выполнением необходим дополнительный шаг; выключен — команда выполняется немедленно после авторизации и серверной проверки полномочий.
4. Отключать запрос подтверждения может только владелец. Для владельца запрос всегда выключен, и его права нельзя изменить через интерфейс.
5. «Сохранить права»: настройки применяются сразу и сохраняются отдельно от ZIP. Не передавайте root-права недоверенным лицам.

НОВЫЙ VPS С ТЕЛЕФОНА (UBUNTU)
1. Купите VPS у хостинга. Для первого входа используйте «Веб-консоль», «VNC», «Console» или «User Data» в браузере телефона. PowerShell или ПК не нужен.
2. Откройте Site Control → «Инфраструктура». Укажите имя и уникальное имя SSH-ключа; для прямого root-доступа выберите пользователя root.
3. Нажмите «Получить публичный ключ». Появится только публичный ключ. Секретный ключ с центрального сервера не скачивается.
4а. Если VPS уже включён: скопируйте «Команду настройки доступа» и выполните её в веб-консоли провайдера, где уже вошли под root. Она создаёт ~/.ssh/authorized_keys и добавляет ключ без удаления прежних. В конце показывает отпечаток SSH сервера.
4б. Если создаёте Ubuntu VPS с поддержкой cloud-init: до первого запуска нажмите «Копировать cloud-init», вставьте текст в User Data провайдера. Такой сценарий зависит от поддержки cloud-init и политики SSH провайдера.
5. В Site Control нажмите «Проверить сервер». Сравните полученный SHA256 отпечаток с тем, что показывает доверенная консоль VPS. Подтверждайте только точное совпадение. Несовпадение — остановить подключение.
6. Заполните адрес/IP, порт SSH, пользователя, имя ключа, службу и проект, нажмите «Сохранить подключение».
7. Нажмите «Подготовить VPS»: папка для файлов проекта создастся на удалённом VPS. Файлы сайта и ZIP публикуются именно на клиентский сервер.
8. В проекте выберите его VPS → «Консоль» → безопасная команда id или uptime. Для полного root нужны SSH-права на целевом сервере и разрешение servers.root в Site Control.
9. Привязка домена и выпуск HTTPS управляются отдельно. У регистратора нужно направить DNS на IP клиента, затем настроить Nginx и TLS на целевом VPS.

ВАЖНО
Новые VPS не подключатся автоматически только по IP, если ещё не установлен и не доверен SSH-ключ. Не отправляйте пароли VPS в Telegram или Site Control. Root-команды и ошибки продолжают записываться в журнал; повторных подтверждений для владельца нет.
