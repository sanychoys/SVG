Обновления продукта

Загрузите один файл, несколько файлов или ZIP. После проверки выберите сервер и опубликуйте.

ZIP сохраняет внутренние пути. Отдельные файлы заменяются по имени или указанному пути; неподтверждённая загрузка не меняет рабочие сайты. Ограничение 30 МБ.

РУКОВОДСТВО

FAQ и инструкции

Подробные пошаговые инструкции для каждого раздела. Начните с интересующей задачи.

01. Как устроен проект?

Проект объединяет файлы сайта, Telegram-бота, сервер клиента, консоль, заявки, обновления, бэкапы и логи. Здесь нет конструктора дизайна: вы загружаете собственный исходный код.

  1. Нажмите «Новый проект».
  2. Укажите название и уникальный slug латиницей.
  3. Откройте карточку.
  4. Загрузите ZIP целиком или отдельные файлы во вкладке «Файлы».
  5. Выберите уже подключённый VPS и нажмите «Опубликовать».

Кнопка «В архив» скрывает проект из списка без удаления данных. Постоянное удаление доступно отдельно в архиве с подтверждением.

02. Как подключить новый VPS по SSH?
  1. Подготовьте сервер с Ubuntu и SSH. Уточните его IP, порт 22, имя обычного пользователя и папку приложения.
  2. На клиентском VPS создайте пользователя с минимально необходимыми правами. Не используйте root для обычного деплоя.
  3. В Site Control откройте «Серверы и SSH». Укажите название ключа, например client1, нажмите «Получить публичный ключ».
  4. Скопируйте строку, которая начинается с ssh-ed25519, и добавьте её в ~/.ssh/authorized_keys нужного пользователя на VPS. Папка ~/.ssh должна иметь права 700, файл authorized_keys — 600.
  5. В отдельной доверенной SSH-сессии на клиентском VPS выполните ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub. Сохраните полученный SHA256 отпечаток.
  6. Укажите IP, порт, пользователя, название ключа, проект и папку.
  7. Нажмите «Проверить сервер»: Site Control покажет свой отпечаток. Сравните его с результатом из доверенной сессии.
  8. Если отпечатки в точности совпадают, вставьте отпечаток в поле и нажмите «Подтвердить SSH-сервер».
  9. Сохраните подключение и в карточке проекта запустите безопасную проверку «Нагрузка».

Не совпал отпечаток? Остановитесь. Проверьте IP и возможную замену VPS — подтверждать такой сервер опасно.

03. Как подключить домен и HTTPS?
  1. Купите домен у регистратора и оформите его на клиента.
  2. Узнайте публичный IPv4 VPS.
  3. В DNS домена создайте запись A для @ на IPv4 сервера. Для www можно добавить CNAME на корневой домен.
  4. Дождитесь применения DNS и убедитесь, что домен направлен на нужный VPS.
  5. На целевом сервере настройте отдельный Nginx server_name example.ru www.example.ru; и путь к опубликованным файлам проекта.
  6. Проверьте sudo nginx -t, затем sudo systemctl reload nginx.
  7. Настройте TLS-сертификат (например, через Certbot) и автоматическое продление.
  8. Откройте https://example.ru и проверьте сертификат, форму заявки и мобильный экран.

Site Control v1.6 не создаёт DNS-записи и Nginx-конфиги автоматически. Эти шаги пока выполняются отдельно на VPS.

04. Как обновить только index.html или весь ZIP?
  1. Откройте проект → «Файлы».
  2. Выберите файл index.html. Если нужно заменить его во вложенной папке, укажите путь, например public/index.html.
  3. Для нескольких файлов загрузите их по отдельности или соберите ZIP с правильной структурой папок.
  4. После проверки найдите подготовленную версию, выберите нужный сервер и подтвердите публикацию.
  5. Перед заменой система создаёт файловый бэкап.
  6. После публикации проверьте сайт. При ошибке используйте вкладку «Бэкапы».

Не загружайте секреты, SSH-ключи и базы данных в обычный архив продукта.

05. Как пользоваться консолью?

В проекте откройте вкладку «Консоль». Для клиента выберите один из его VPS. Для «Нашей платформы» по умолчанию доступен текущий сервер — никакого SSH-подключения не нужно.

  1. Для безопасной проверки нажмите «Нагрузка», «Диск» или «RAM».
  2. Для своей команды введите её в поле и подтвердите выполнение.
  3. Прочитайте результат в чёрном окне консоли. Команда ограничена временем выполнения.

Локальные команды Site Control выполняются без root-прав, а SSH-команды — с правами настроенного пользователя клиента. Опасные действия и перезапуск могут требовать отдельной настройки прав на VPS.

06. Как работают бэкапы?
  1. Откройте проект → «Бэкапы».
  2. Выберите VPS (в «Нашей платформе» по умолчанию локальная папка).
  3. Нажмите «Создать копию» и дождитесь появления новой записи.
  4. Кнопка «Скачать» сохраняет ZIP на телефон.
  5. Кнопка «Восстановить» вернёт файлы выбранной копии, предварительно сделав страховочную копию текущих файлов.
  6. Можно импортировать ранее скачанный ZIP в список, не восстанавливая его сразу.

Важно: файловый бэкап не содержит полную резервную копию PostgreSQL/SQLite вне папки проекта. Перед критическими обновлениями сохраняйте базу данных отдельно.

07. Где найти логи и скачать их?

Откройте проект → «Логи» и нажмите Telegram, Сайт/API, Обновления или Сервер. Журнал появится в окне; ниже доступны «Копировать» и «Скачать TXT». В «Нашей платформе» те же кнопки показывают собственные журналы Site Control. Ошибки в технических логах сохраняются с traceback.

Если журнал пуст — это не обязательно поломка: например, после запуска без обращений ещё не было записей.

08. Как подключить Telegram-бота клиента?
  1. Откройте официальный @BotFather.
  2. Создайте бота командой /newbot и задайте имя и username.
  3. Скопируйте токен BotFather — никому не пересылайте его в публичных чатах.
  4. Откройте нужный проект → «Telegram» и вставьте токен.
  5. После подключения проверьте бота командой /start и тестовую заявку.

Каждый клиентский бот использует общую платформу, но связан только со своим проектом. Смена токена проводится через BotFather и повторное подключение.

09. Почему Mini App пишет «Доступ закрыт»?
  1. Откройте личный чат именно с главным ботом Site Control.
  2. Отправьте /start и нажмите inline-кнопку «Открыть Mini App».
  3. Проверьте, что используете Telegram-аккаунт администратора; владелец Site Control имеет ID 382257126.
  4. Если данные Telegram устарели, закройте Mini App и откройте заново через кнопку.
  5. Если подпись не подтверждена, проверьте правильность BOT_TOKEN работающего главного бота и HTTPS URL приложения на сервере.
  6. Откройте «Логи» → «Сайт/API», чтобы увидеть тип отказа без раскрытия токена.

Приложение не принимает произвольный ID пользователя — доступ выдаётся только после проверки настоящей подписи Telegram.

10. Как добавить или удалить администратора?
  1. Откройте «Администраторы».
  2. Уточните точный Telegram ID нового участника.
  3. Введите его в небольшое поле и нажмите «Добавить».
  4. Подтвердите выдачу прав. Пользователь сможет открыть Mini App из главного бота.
  5. Чтобы отозвать доступ, нажмите «Удалить доступ» в его карточке и подтвердите.

Главный владелец не может быть удалён. Список администраторов хранится отдельно от файлов обновления и бэкапов продукта.
