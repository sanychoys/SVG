# SVGTracker V33 — Центр аккаунта

Обновление на основе V32 `SVGTracker_V32_Profile_Redesign(1).zip`. Сохранены основные домены проекта, авторизация, финансы, тренировки, заметки, расписание, Telegram-бот, а также механика автоматического деплоя.

## Что изменилось

- Вместо дубля главной страницы в профиле теперь компактный **центр аккаунта** с личной карточкой Telegram, контактами, приватностью, уведомлениями, устройствами и выгрузкой данных. Карточки «активные сферы», «сегодня потрачено», «заметки», «тренировки» и аналогичные дубли в профиле убраны; на главной они остаются.
- **Без редактора профиля**: имя, username и аватар только считываются из Telegram; можно скопировать свои Telegram username и ID.
- **Приватность**: отдельный экран с переключателем `share_busy`. Переключатель обращается к существующим API и таблице `notification_preferences`, поэтому влияет на доступ друзей к занятым интервалам в расписании. Значение по умолчанию — «выключено». Есть переход к списку заблокированных пользователей.
- **Безопасность**: список активных веб-сессий с датами последней активности и окончания действия; завершение выбранной чужой веб-сессии или всех остальных после подтверждения. Текущая веб-сессия не может быть закрыта через этот интерфейс; для неё есть отдельный выход. Telegram Mini App не выдаёт браузерных сессий и не перечисляется в разделе.
- **Мои данные**: выгрузка своего аккаунта в JSON через защищённый API, включая тренировки, финансы, расписание, заметки (архивные тоже), сведения о друзьях и настройки. Прикреплённые файлы заметок включены только как метаданные; содержимое вложений не выгружается. Экспорт требует авторизации.
- **Исправления**: избавление от второго обработчика уведомлений на одной кнопке; корректная история переходов назад между вложенными экранами; ограничение клавиатурной навигации диалогом; предотвращение применения запоздалого ответа профиля после выхода и очистка кешей безопасности при выходе; синхронизация `share_busy` между двумя интерфейсами.
- Обновлены версия API и параметры `?v=33` статических ресурсов, чтобы не оставались старые ресурсы в кешах.

## Новые серверные маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/profile/security` | Текущие активные веб-сеансы авторизованного владельца, без cookie и токенов |
| `POST` | `/api/profile/sessions/revoke` | `{ "mode": "others" }` или `{ "mode": "one", "session_id": "<20 hex>" }`; только собственные веб-сеансы |
| `GET` | `/api/profile/export` | JSON-экспорт данных текущего авторизованного аккаунта (`Cache-Control: no-store`) |

Существующие `GET/PUT /api/notifications/preferences` продолжают обслуживать настройку `share_busy`.

## Проверки

- `node --check script.js` и `node --check product.js` — пройдены.
- `python -m py_compile main.py finance_db.py product_api.py product_db.py` — пройдена.
- `python -m unittest discover -s tests -v` — 3 теста: разграничение доступа между пользователями к сессиям, запрет закрытия текущей сессии через список, валидация идентификатора и сохранение настроек приватности.
- Предпроверка из `deploy/admin_deploy.py`: уникальность HTML ID, наличие всех обработчиков inline-кнопок и статических ресурсов — пройдена.
- Локальный браузерный рендер в Chromium: вложенные экраны профиля отображаются, ошибок выполнения JS не замечено, горизонтального переполнения на ширинах 320px/390px нет. Реальные fetch-запросы проверяются после установки на окружении с разрешённым доступом к HTTP/авторизованной базой: без него сетевые данные в тестовом браузере недоступны.

## Установка

Загрузи ZIP через существующий админ-деплой, не затрагивая `config.py`, `.env`, базу `svgtracker.db` и личные пользовательские файлы. Новые таблицы не требуются: используется имеющаяся структура `web_sessions` и `notification_preferences`. После установки перезапусти сервис штатным деплой-скриптом и проверь в двух средах: Telegram Mini App и сайт через Telegram-login.

Не размещай экспортированные JSON-файлы в публичных директориях или репозитории.
