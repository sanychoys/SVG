# Site Control v1.1 — чистый Telegram-бот, компактные уведомления, обновлённая панель

Это готовый **ZIP-пакет исходного обновления**, предназначенный для загрузки через существующий Telegram ZIP-deployer Site Control v1.0 / совместимый механизм SVGTracker V48. Публикацию на реальном VPS необходимо выполнить и проверить отдельно; архив протестирован локально.

## Что изменилось

- Административный бот: короткое главное меню «Открыть панель / Состояние / Последнее изменение / Обновить ZIP / Резервная копия»; без громоздких справок о старом трекере, диске, Git и длинных повседневных логах.
- Telegram-меню команд: только `/start`, `/status`, `/last`, `/backup`; остальные технические команды не удалены из программы, но скрыты из пользовательского списка, чтобы сохранить восстановление и управление админами.
- Полные ошибки обновления и отката теперь передаются в Telegram отдельными частями при необходимости; в `deploy_status.json` и диагностическом JSON-журнале сохраняются технические подробности.
- Успешный ZIP-deploy сообщает только дату, время и количество изменённых файлов; «последнее изменение» находит свежую запись в журнале проектов или установки.
- `/status`: дата/время, статус службы, реальная проверка HTTP `127.0.0.1:8000/api/test`, количество сайтов и незакрытых новых заявок, последнее значимое изменение.
- Упрощён клиентский бот: кнопки «Заявки», «Товары и услуги», «Данные сайта», «Как изменить». Существующие команды изменения товаров, цен, контента **сохранены** и работают; `/help` показывает подробную инструкцию.
- Старый watchdog переведён на Site Control: здоровый сервер не генерирует уведомлений; о восстановлении только время и изменение, при ошибке — подробности. Исправлен ошибочный контроль «активности развёртывания» по дате файла блокировки.
- Веб-панель: выровненные элементы, упрощённые русские подписи, одинаковые карточки и кнопки, адаптивная сетка для телефона, учтены настройки уменьшения анимаций.

## Что оставлено намеренно

- ZIP-установка через документ в Telegram; автоматическая резервная копия перед обновлением, проверка API, синхронизация с GitHub, автоматический откат при проблеме.
- `/rollback` — ручной откат с подтверждением.
- `/admin_add ID`, `/admin_remove ID`, `/admins` — управление составом администраторов.
- `/login КОД` — вход с сайта через Telegram.
- `/deploy_check` — состояние последнего ZIP-обновления, кратко при успехе, подробно при ошибке.
- Возможность получать заявки от индивидуальных клиентских ботов и редактировать содержимое сайтов.

## Порядок установки

1. В работающем главном боте выполните `/backup` и **скопируйте резервную копию с VPS отдельно**. Проверка `/backup` сама по себе не означает, что копия сохранена вне сервера.
2. Отправьте `Site_Control_V11_Clean_Bot_and_Logs.zip` как документ, не распаковывая.
3. Подтвердите «Установить ZIP» и дождитесь результата от сервера.
4. Нажмите «Состояние» или отправьте `/status` — проверьте «Сервис: работает», «API: работает».
5. Откройте Site Control в браузере и убедитесь, что интерфейс и редактирование сайта доступны.
6. Проверьте `/last`, `/deploy_check`, загрузку изображения и отдельного клиентского бота, а также тестовую заявку.

**Важное:** система проверяет GitHub/VPS перед обновлением; если Git diverged или не работает `systemd-run`, установщик может отклонить архив. Это штатное ограничение механизма V48, а не повод отключать проверку.

## Что не меняется

- Не удаляются проекты Site Control, заявки, публикации и токены клиентских ботов из `/var/lib/sitecontrol`.
- Сохраняется файл конфигурации `config.py`, главный токен BotFather, реестр администраторов.
- Старые данные SVGTracker не затрагиваются. Имя systemd-сервиса остаётся `svgtracker.service` ради совместимости с текущим VPS.
- Произвольные сервера/домены не создаются автоматически этим ZIP.

## Проверки, выполненные локально

- `python -m pytest -q tests/test_sitecontrol.py tests/test_sitecontrol_minimal_bot.py`
- `python -m compileall -q` для Python-файлов.
- `node --check script.js` и `node --check product.js`.
- Проверка контракта HTML/JS старого ZIP-deployer.
- Визуальная проверка в Chromium для 390px и 1440px, без горизонтальной прокрутки на главной.

На самом VPS живой Telegram, GitHub push, systemd и сетевой health-check проверить из архива невозможно. При ошибке **не отправляйте ZIP повторно без анализа сообщения**, воспользуйтесь `/deploy_check` и резервной копией.
