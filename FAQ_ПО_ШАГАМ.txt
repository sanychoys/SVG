SITE CONTROL v1.6 — ПОДРОБНОЕ РУКОВОДСТВО

01. ЧТО ЗДЕСЬ СЧИТАЕТСЯ ПРОЕКТОМ
Клиентский проект объединяет исходники сайта и бота, связи с серверами, заявки, обновления, логи и бэкапы. Визуального конструктора сайта нет. Вы передаёте ZIP или изменённые файлы, а Site Control управляет версиями и публикацией.

02. ПОДГОТОВКА НОВОГО VPS КЛИЕНТА (UBUNTU)
А) Получите IP-адрес, порт SSH и пароль/ключ от панели провайдера.
Б) Убедитесь, что SSH работает и вход в сервер доступен. Через текущую сессию оператора создайте обычного пользователя, например scdeploy; не назначайте ему безусловные root-права.
В) Откройте Site Control → «Серверы и SSH». В поле «Название ключа» впишите что-то понятное, например cafe1; нажмите «1. Получить публичный ключ».
Г) Появится строка ssh-ed25519 ... . Это ПУБЛИЧНЫЙ ключ, его можно скопировать на сервер. ПРИВАТНЫЙ ключ на свой телефон и в чат не пересылайте. Он хранится на VPS Site Control.
Д) На клиентском VPS для пользователя scdeploy создайте ~/.ssh, если её ещё нет, и поместите всю строку в ~/.ssh/authorized_keys. Проверьте права: chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys; владелец должен быть scdeploy.
Е) На этом VPS в уже доверенном SSH-терминале выполните: ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
Ж) Получится отпечаток SHA256:... Это идентификатор сервера, а не пароль и не токен. Вернитесь в Site Control и укажите IP, порт, логин, название ключа, службу и папку продукта; нажмите «3. Проверить сервер».
З) ДВА отпечатка SHA256 должны совпасть: из консоли VPS и из Site Control. Если они не совпадают, НЕ подтверждайте. Проверьте, тот ли IP и не был ли сервер заменён.
И) Скопируйте проверенный отпечаток в «Отпечаток из консоли VPS», нажмите «Подтвердить SSH-сервер», потом «Сохранить подключение».
К) Откройте проект → «Консоль», выберите подключённый VPS, нажмите «Нагрузка». Если соединение не получилось, проверьте порт SSH, firewall, права authorized_keys, пользователя и лог сервера.

03. КАК ПОДКЛЮЧИТЬ ДОМЕН К VPS
А) Зарегистрируйте домен на реквизиты клиента; сохраните доступ к регистратору.
Б) Откройте DNS в панели регистратора, добавьте A-запись для @ на IPv4 клиента; для www используйте CNAME на корень (если провайдер поддерживает).
В) Если нужен IPv6, его AAAA-запись должна указывать на работающий IPv6 клиента, иначе её лучше не создавать.
Г) Дождитесь обновления DNS. В Nginx на клиентском VPS настройте отдельный виртуальный хост server_name example.ru www.example.ru и правильную папку с сайтом. Если сайт работает через FastAPI, настройте proxy_pass на локальный порт приложения. Открывайте только необходимые порты.
Д) Выполните sudo nginx -t; при успешной проверке — sudo systemctl reload nginx.
Е) Выпустите сертификат Let's Encrypt при помощи Certbot или другого поддерживаемого ACME-клиента, включите автопродление.
Ж) Проверьте https://домен, сертификат, мобильную страницу и заявки. Автоматическая настройка DNS/Nginx/TLS в версии 1.6 не реализована.

04. КАК ЗАМЕНИТЬ ОДИН ФАЙЛ
Проект → Файлы → выбрать index.html. Если путь на сервере /srv/cafe/public/index.html, в поле пути укажите public/index.html. Нажмите «Проверить и загрузить», выберите сервер и «Опубликовать». Перед заменой файлов создаётся бэкап.

05. КАК ПОЛНОСТЬЮ ОБНОВИТЬ ПРОЕКТ ZIP
Соберите ZIP, внутри которого лежит структура файлов проекта, а не произвольные системные каталоги. Загрузите ZIP во вкладке «Файлы». Проверьте перечень файлов в версии, выберите правильный VPS и подтвердите публикацию. После обновления проверьте сайт. Если клиентский backend требует перезапуска службы, выполните его отдельно на сервере с разрешёнными правами.

06. КОНСОЛЬ
Вкладка «Консоль» умеет выполнять готовые команды, например загрузка, диск и память. Ручную команду вводите осмысленно: она действительно выполняется с правами выбранного пользователя после подтверждения. На клиентском VPS это SSH-пользователь, для нашей платформы — ограниченный сервисный пользователь уже работающего сервера. У консоли есть лимиты времени и объёма вывода. Не используйте непроверенные команды из Интернета.

07. БЭКАПЫ
Создать копию → дождаться записи → Скачать ZIP для хранения на телефоне или внешнем диске. Для восстановления выберите конкретную копию и нажмите «Восстановить». Перед восстановлением система создаёт страховочную копию. Если есть скачанный ZIP, его можно сначала импортировать в список без немедленного применения. Бэкапы файлов не содержат автоматически сторонние базы данных или данные сторонних сервисов.

08. ЖУРНАЛЫ
В каждом проекте вкладка «Логи»: Telegram-бот, Сайт/API, Обновления, Сервер. Нажмите тип — увидите содержимое прямо на странице; «Копировать» поместит его в буфер, «Скачать TXT» сохранит файл. Журналы сайта и бота для клиентского проекта изолированы по ID проекта, полный технический журнал Site Control смотрите в «Нашей платформе». У ошибок публикации сохраняется traceback.

09. TELEGRAM-КЛИЕНТА
Через @BotFather создайте бота, получите токен и вставьте его только в защищённую форму проекта. Проверьте вебхуки на HTTPS, указанные в настройках Site Control, и роль клиента. Никогда не публикуйте токен в коде фронтенда или скриншотах.

10. MINI APP ГЛАВНОГО БОТА
В личном чате с главным ботом выполните /start → «Открыть Mini App». Подписанные данные Telegram проверяются backend, затем проверяется список администраторов. Владелец — ID 382257126, остальные администраторы хранятся отдельно. Отдельный логин в Mini App не нужен. При отказе закройте и откройте окно заново, нажмите «Повторить проверку» и прочитайте причину. В обычном браузере используется авторизация через Telegram-код. Ни одна из этих проверок не заменяется простым вводом ID.

11. УПРАВЛЕНИЕ АДМИНИСТРАТОРАМИ
Раздел «Администраторы» → Telegram ID → «Добавить» → подтверждение. Участник получит полный доступ. «Удалить доступ» немедленно отзывает права после подтверждения. Главного владельца удалить нельзя. admins.json находится за пределами архива и не удаляется деплоем.

12. УДАЛЕНИЕ ПРОЕКТА
Откройте карточку → «В архив». Проект скрывается из активного списка, но работающий сайт клиента остаётся на сервере. В разделе «Архив проектов» можно вернуть его. Для полного удаления записи из Site Control отключите связанные VPS, нажмите «Удалить навсегда» и введите точный slug. Бэкапы файлов сохраняются для ручной страховки. Файлы/домены на чужом VPS этим действием НЕ удаляются. Это сделано специально для защиты от случайной потери клиентских данных.

13. ЕСЛИ ПОСЛЕ ОБНОВЛЕНИЯ ЧТО-ТО НЕ РАБОТАЕТ
Сначала сохраните /status и /logs, затем проверьте наличие API (/api/test), состояние systemd-службы, корректность Nginx и актуальность фронтенда без кеша браузера. Отдельно проверьте данные Telegram Mini App. Если существующий установщик не может вызвать systemd-run, обычная загрузка нового ZIP не поможет — требуется исправить установщик по SSH, без снятия системных ограничений.
