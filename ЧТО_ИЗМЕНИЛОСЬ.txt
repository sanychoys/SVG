SITE CONTROL v1.11 — ИСПРАВЛЕНИЕ ЛОКАЛЬНОЙ КОНСОЛИ

Причина: на VPS Python 3.14 при попытке изменить UID/GID дочернего процесса
получал PermissionError: [Errno 1] Operation not permitted. HTTP 502 возникал
ещё до выполнения команды. Ограничения наложены операционной системой/systemd,
а не Telegram и не правами администратора в Site Control.

Исправления:
1. Кнопки «Нагрузка», «Диск», «RAM», «Сервис», «Логи» и «Файлы» в разделе
   «Наша платформа → Консоль» получают данные непосредственно через Python
   и системные файлы ОС, без запуска дочерних процессов и смены UID/GID.
2. «Логи локального сервера» в Site Control читают последние события из
   локального журнала Site Control; HTTP 502 из-за смены пользователя устранён.
3. Блок консоли сообщает, если веб-служба запущена с UID 0 (root):
   произвольные команды в таком режиме запрещены, чтобы исключить root-shell
   из веб-интерфейса. Несколько точных команд проверки доступны безопасно.
4. Ошибка неподдерживаемой ручной root-команды возвращается как понятное
   сообщение HTTP 409, а не полный traceback и HTTP 502.
5. Добавлены проверки ограничения прав, веб-API, логов и второго администратора.
6. Обновлена версия клиентских ресурсов sc1110 для сброса кеша Telegram.

Не изменялось:
- логика проектов и удалённых SSH-серверов;
- Telegram Mini App и его авторизация;
- структура базы данных и список администраторов;
- механизм загрузки ZIP/резервных копий;
- оформление UI за исключением подсказки о правах консоли и номера версии.

ОГРАНИЧЕНИЕ: редактирование системных файлов и произвольный shell на
центральном VPS требуют отдельного непривилегированного исполнителя.
Этот ZIP его не устанавливает и не меняет unit-файл systemd автоматически.
