SITE CONTROL v1.17 — ЕСЛИ ОБНОВЛЕНИЕ ЧЕРЕЗ САЙТ НЕ УСТАНАВЛИВАЕТСЯ

Это означает, что прежняя systemd-служба не разрешает запуск установщика.
Веб-приложение не должно самостоятельно выдавать себе эти привилегии.

Разовая настройка с телефона через веб-консоль VPS-провайдера (вход с sudo):

1. Для активации защищённого установщика, если файл уже имеется на сервере:
cd /var/www/SVG && sudo python3 deploy/configure_update_service.py
sudo systemctl is-active sitecontrol-updater.path

2. Для активации root-исполнителя, если код Site Control v1.17 уже установлен:
cd /var/www/SVG && sudo python3 deploy/configure_root_executor.py --web-user root --owner-id 382257126 --enable-root
sudo systemctl is-active sitecontrol-root-executor.service

Если Site Control работает от другого Linux-пользователя, вместо --web-user root укажите его Linux-имя из `systemctl show -p User --value svgtracker.service`.
Если команда ничего не выводит, служба часто запускается от root (но это нужно проверить).

Если обновление по-прежнему недоступно, файлы версии v1.17 требуется сначала развернуть на VPS из архива через файловый менеджер VPS/SFTP и штатный установщик. Нельзя полагаться на команду включения root, если версия этого файла отсутствует на рабочем сервере.

После выполнения пункта 2 откройте Mini App → Наша платформа → Консоль → Проверить доступ.
Данные, токены и список администраторов не входят в ZIP и не должны заменяться.
