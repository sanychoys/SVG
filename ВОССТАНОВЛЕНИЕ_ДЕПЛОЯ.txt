SITE CONTROL — ЕСЛИ ZIP НЕ УСТАНАВЛИВАЕТСЯ (systemd-run failed)
==============================================================

Симптом: бот присылает «Ошибка запуска», и обновление не применяется.
Причина: текущему процессу недоступен запуск systemd-run либо systemd
не даёт нужных прав. Простая загрузка ZIP не исправит это до установки.

1. Подключитесь к своему VPS через SSH (можно с телефона, Termius).
2. Сделайте резервные копии конфигурации и данных — НЕ удаляйте БД.
3. Посмотрите статус службы: sudo systemctl status svgtracker.service
4. Посмотрите последнюю ошибку: sudo journalctl -u svgtracker.service -n 50 --no-pager
5. Отправьте ZIP текущему боту как документ; при ошибке запуска ZIP
   может остаться в /var/lib/svgtracker-admin/incoming/. НЕ угадывайте
   имя — убедитесь в списке и содержимом архива перед установкой:
     sudo ls -lht /var/lib/svgtracker-admin/incoming/*.zip
     sudo unzip -l /ПОЛНЫЙ/ПУТЬ/К/АРХИВУ.zip
6. Если в папке incoming есть ИМЕННО этот проверенный архив, попробуйте
   вручную запустить имеющийся установщик с SSH-сессии администратора:
     sudo python3 /var/www/SVG/deploy/admin_deploy.py deploy /ПОЛНЫЙ/ПУТЬ/К/АРХИВУ.zip --admin-chat 382257126
   Замените путь на фактический из пункта 5. Установщик может также
   остановить установку при проблемах GitHub или проверке API.
7. Проверьте статус: sudo systemctl status svgtracker.service
   И GET https://ВАШ-ДОМЕН/api/test в браузере.

ВНИМАНИЕ: команда выполняет реальную замену production после проверок
установщика. Сначала обязательно сохраните резервную копию отдельно
от сервера и проверьте содержание ZIP. Если нет sudo либо SSH,
нужен доступ владельца VPS: один только ZIP не может выдать привилегии.

Если ваша старая версия поддерживает другие пути, уточните их через
systemctl cat svgtracker.service и содержимое папки проекта. Не
переписывайте unit-файл вслепую и не выдавайте боту полный sudo-доступ.
